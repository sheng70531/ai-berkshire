# 報告索引機制說明

`reports/` 下有 2000+ 份報告。為了讓人和機器都能找到它們，這裡維護一層**索引**，
不改動任何報告文件本身。

## 產物

| 文件 | 用途 |
|------|------|
| `reports/README.md` | 人讀索引：最近更新 + 按公司/專題/大師分組 |
| `reports/index.json` | 機器可讀清單，供腳本、網頁、檢索消費 |
| 根 `README.md` 中的 `REPORTS-INDEX` 塊 | 倉庫首頁的研究入口，自動刷新 |

三份產物全部由 `tools/reports_index.py` 生成，**不要手工編輯**。

## 用法

```bash
# 寫完新報告後跑一次
python3 tools/reports_index.py

# CI 用：只檢查是否過期，不寫盤
python3 tools/reports_index.py --check
```

## 元數據從哪來

腳本按以下優先級推斷每份報告的標題、日期、類型與歸屬：

1. **文件自帶 YAML front-matter**（可選，優先級最高）
2. **文件名**：`公司-主題-YYYYMMDD.md` 中的 8 位日期
3. **正文**：前 15 行裡的 `2026-09-07` / `2026年9月7日`
4. **git 最近提交時間**

寫新報告時，**只要文件名帶 `-YYYYMMDD` 後綴、正文首行是 `# 標題`，就不需要額外做任何事**。

需要覆蓋推斷結果時，在文件開頭加 front-matter：

```markdown
---
title: 拼多多 2026Q2 財報精讀
date: 2026-08-25
type: 財報
---

# 正文標題
```

`type` 可選值：`研究` `財報` `深度系列` `橫評對比` `估值倉位` `組織管理` `篩選` `公眾號` `底稿`。

## 歸屬分類

頂層目錄歸到哪一類，由 `reports/_index/config.json` 決定：

- `companies`：公司目錄（默認。新建的公司目錄不用登記也能正常索引）
- `themes`：跨公司專題、產業鏈研究
- `masters`：大師方法論研究
- `screens`：篩選與推演的**中間產物**（召回池等），在索引裡只顯示目錄和數量，不逐條列出
- `aliases`：同一家公司的多個目錄名合併到一個規範名，例如 `Alibaba` → `阿里巴巴`

新增專題或篩選池目錄時，記得往 `config.json` 對應數組裡加一行，否則會被當成公司。

## 隱私

腳本會調用 `git check-ignore` 過濾掉被 `.gitignore` 命中的文件
（例如 `reports/portfolio-latest.md` 組合報告），確保本地私有內容不會被寫進公開索引。
