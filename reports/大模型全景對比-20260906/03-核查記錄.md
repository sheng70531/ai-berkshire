## 重點事實核對

- 當前 API、發佈日期權重和更新後的 API 快照分別判斷。DeepSeek-V4 的後續 API 版本不自動視為與初始公開權重逐字節一致；Qwen3.8 API 的能力也不直接套到其公開文本權重上。
- GLM-5.3 與 GLM-5.2 的倉庫張量總數均為 753,329,940,480。報告未把 GLM-5 原版的 40B 激活參數直接當作 5.3 的新披露。量化打包、額外預測層等統計口徑仍需工程層面核對。
- Kimi K3、Qwen3.8、GLM-5.3、MiniMax M3 和 Mistral Modified MIT 的商業條款分別讀過正文；不同閾值涉及的收入期間、關聯方範圍和適用業務不同。
- NVIDIA Nemotron 3 Ultra 當前模型卡鏈接 OpenMDW 1.1，Super 鏈接 NVIDIA Nemotron Open Model License；兩者分別列示。Solar Open 權重採用 Upstage Solar License，代碼的 Apache 2.0 不能替代權重許可。
- 獨立能力分數引用 Artificial Analysis 的 2026-09-03 Astra 專題，保留模型檔位、工具環境與日期。廠商代碼評測保留來源及不同測試環境限制，未把兩個指數或兩種證據混成統一總排名。
- 未找到官方參數的 GPT、Claude、Gemini 等旗艦保留“未披露”。ERNIE 5.1 的約 0.8T 明確是基於官方相對比例的推算。

## 算術與文檔核查

按項目要求運行 `python3 tools/financial_rigor.py calc --expr ...` 共 44 次，覆蓋 4 個固定 token 用量的 API 費用示例、1 個參數比例推算和 39 個權重存儲量單元格。輸出保存為 [算術記錄](</Users/linxuan/ai-berkshire/reports/大模型全景對比-20260906/evidence/arithmetic.json>)。

此外，用 Python Decimal 從十進制字符串獨立核對全部 44 項，並將存儲表的 39 個單元格逐個與計算結果比較，全部一致。工具的顯示行會對金額保留兩位小數，因此 GLM 費用採用完整值 0.184 美元。`2.4/3` 的工具內部輸出出現浮點尾差，Decimal 結果為精確 0.8；未將尾差帶入報告。此次沒有修改項目計算工具。

兩份報告均運行了項目審計提取器：

```text
python3 tools/report_audit.py extract --report <報告路徑> --seed 20260906 --dry-run
```

旗艦報告提取 108 個數據點、抽樣 17 個；參數報告提取 183 個數據點、抽樣 28 個。原始輸出保存為 [旗艦報告抽檢提取](</Users/linxuan/ai-berkshire/reports/大模型全景對比-20260906/evidence/01-report-audit.txt>)和 [參數報告抽檢提取](</Users/linxuan/ai-berkshire/reports/大模型全景對比-20260906/evidence/02-report-audit.txt>)。

**這個工具主要針對財務報告，運行成功不等於技術事實審計通過。** 它會把 GPT-6 中的版本號識別成負數，把模型編號當成財務數據，並提示查詢股票數據網站。因此，此次僅保留提取結果，參數與許可逐項回到官方技術來源核對，沒有據此生成虛假的“全部審計通過”結論。

補充文檔檢查包括表格列數、文件內鏈接目標存在性、廠商行數、計算表一致性及證據清單生成。結果保存在 [文檔檢查記錄](</Users/linxuan/ai-berkshire/reports/大模型全景對比-20260906/evidence/document-checks.json>)。
