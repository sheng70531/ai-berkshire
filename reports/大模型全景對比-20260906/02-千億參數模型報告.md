# 千億參數大模型：規模、開放程度與部署成本

數據截止：2026 年 9 月 6 日，北京時間。範圍：總參數至少 100B 的通用語言、推理、代碼及視覺語言模型；同一模型的量化版和部分日期快照合併。資料來自官方模型卡、許可證與原始論文。本報告為技術研究。

配套報告：[全球旗艦能力與價格對比](</Users/linxuan/ai-berkshire/reports/大模型全景對比-20260906/01-全球旗艦模型對比報告.md>)。

## 最重要的結論

**千億參數並不等於每次都計算千億參數，也不等於比小模型更強。** 當代很多大模型採用混合專家架構（MoE），權重總量決定存儲規模，每次激活的參數只佔其中一部分。與此同時，現代後訓練、數據、工具與推理預算足以使參數較小的模型在特定任務中超過較大的模型。

**開源狀態必須按具體模型及版本判斷。** DeepSeek-V4、Qwen3.5、Hy3、Command A+、K-EXAONE 2.0 有較寬鬆的權重許可；Kimi K3、Qwen3.8-2.4T、GLM-5.3、MiniMax M3 等附有不同商業條件。更早的 DeepSeek-V3 初版也不能自動按後來 V3.1/V3.2 的 MIT 許可處理。逐項來源見以下清單。

本清單覆蓋主要可核實產品、開放權重及歷史研究模型，不聲稱窮盡全世界所有訓練實驗、合併模型與社區微調。沒有公開參數的旗艦不會被猜測成“萬億模型”。

## 計數規則：先把 B、T 和激活參數分開

| 表達 | 換算或含義 |
|---|---|
| 1B 參數 | 10 億參數 |
| 100B 參數 | 1,000 億參數，即本文“千億”門檻 |
| 1T 參數 | 1 萬億參數，即 1,000B |
| 235B-A22B | 總參數約 2,350 億，每 token 激活約 220 億 |
| 128B 稠密模型 | 每次前向傳播使用基本全部主幹參數；不是 MoE 式只選擇少量專家 |
| 激活參數 | 每 token 調用的模型部分；它不是顯存佔用，也不是精確 FLOPs 或響應速度 |

本文主表優先採用開發者公佈的模型規模。附加預測層（MTP）、視覺編碼器、嵌入層及量化相關張量是否計入，不同來源可能不同，因此保留“約”“主幹”“倉庫張量統計”等標籤。訓練語料 tokens 數、上下文長度和參數個數是三件不同的事。

## 千億模型究竟需要多大內存

如果所有參數均以相同精度保存，**僅權重**的理論體積為：

`參數個數 × 每個參數的位數 ÷ 8`。

下表為十進制 GB，1GB = 10^9 字節。BF16/FP16 為 2 字節，8 bit 為 1 字節，4 bit 為 0.5 字節。表中量化是假設，不保證每款模型都有對應精度的可用、等質量實現。

| 參數規模示例 | 16 bit 權重 GB | 8 bit 權重 GB | 4 bit 權重 GB |
|---|---:|---:|---:|
| 100B 門檻 | 200 | 100 | 50 |
| 117B，gpt-oss 主規模 | 234 | 117 | 58.5 |
| 122B | 244 | 122 | 61 |
| 196B | 392 | 196 | 98 |
| 320B | 640 | 320 | 160 |
| 397B | 794 | 397 | 198.5 |
| 428B | 856 | 428 | 214 |
| 671B | 1,342 | 671 | 335.5 |
| 753B 示例口徑 | 1,506 | 753 | 376.5 |
| 1.02T | 2,040 | 1,020 | 510 |
| 1.6T | 3,200 | 1,600 | 800 |
| 2.4T | 4,800 | 2,400 | 1,200 |
| 2.8T | 5,600 | 2,800 | 1,400 |

以上已使用項目精確算術工具複核；不是採購配置。實際部署還要增加 KV cache 或線性注意力狀態、量化 scale、激活、通信緩存、框架工作區與內存餘量。不同 MoE 專家會在不同 token 被調用，**不能只按“激活 13B”給 284B 模型準備 13B 權重的顯存**。也可以將部分權重放在 CPU 內存、磁盤或跨節點加載，但速度與併發會受內存帶寬和互聯影響。

例如，gpt-oss-120b 官方說明可以用原生量化方案運行在單塊 80GB GPU 上；這不等於所有 120B 模型的所有精度、上下文與併發都能使用同一配置。Qwen3-235B 的模型卡則對約 1M 上下文給出約 1,000GB 總 GPU 內存的示例要求，說明緩存和運行配置的影響很大。[gpt-oss 模型卡](https://huggingface.co/openai/gpt-oss-120b)、[Qwen3 長上下文說明](https://huggingface.co/Qwen/Qwen3-235B-A22B-Instruct-2507)。

## 從參數報告得到的選擇結論

如果主要通過 API 使用，優先比較任務成功率、費用和延遲；廠商沒披露參數並不妨礙評估。若要自行部署，先選擇許可證和硬件預算，再篩模型能力。想試千億級，不必從 Kimi K3 或 Qwen3.8 這樣的數萬億模型開始；117B 至 196B 的稀疏模型已經提供多種推理和工具任務路線。

**模型能力、參數規模、可下載性、商業授權，需要分別判斷。** 它們有關聯，但任何一個都不能替代另外三個。

## 核查與侷限

參數來自開發者模型卡或原始論文；GLM-5.2/5.3 等另外檢查了官方倉庫元數據。許可證以具體權重倉庫的正文或明確鏈接為準，不能只看網頁上的“open source”宣傳詞。對需要賬號接受條款的倉庫，只讀取公開頁面與元數據，沒有替用戶接受許可。

本次沒有運行模型推理、下載全部權重或驗證訓練可復現性。部分模型的精確激活量、最新 API 與公開權重對應關係仍未披露；這些空白已保留。歷史條目用於理解規模演進，不能直接放入當代能力排行榜。完整核查記錄見 [審計說明](</Users/linxuan/ai-berkshire/reports/大模型全景對比-20260906/03-核查記錄.md>)。
