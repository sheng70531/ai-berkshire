# 看懂 Kimi K3：2.8 萬億參數的開源前沿模型

> 寫作日期：2026-07-20（發佈後第 4 天）。本文所有關鍵數字經過多信源交叉核實，廠商自報且尚無法獨立驗證的數字均已單獨標註。技術報告和權重預計 2026-07-27 前發佈，屆時部分結論需要更新（見文末"待解問題"）。

## 一句話總結

Kimi K3 是月之暗面 2026-07-16 發佈的 2.8 萬億總參數稀疏 MoE 旗艦模型，靠混合線性注意力（KDA）+ 跨層殘差檢索（AttnRes）等一攬子架構改動把擴展效率做到 K2 的約 2.5 倍（官方口徑），獨立評測確認它站上了全球第三檔——與 Claude Opus 4.8、GPT-5.5 同檔，Agent 類任務是它最強的一面，但整體仍落後 Claude Fable 5 和 GPT-5.6 Sol。它同時承諾 7 月 27 日前開放全部權重，如果兌現，將是首個 3T 級別的開源模型。

## 二、架構創新：相對 K2 改了什麼

理解 K3 的變化，要先錨定 K2 的基線（K2 有公開技術報告 arXiv:2507.20534 和開放權重，是全文最紮實的部分）：

**K2 基線：**1.04T 總參數 / 32B 激活，注意力用 MLA（沿襲 DeepSeek-V3 設計，但專家數 256→384、注意力頭 128→64），優化器用 MuonClip（Muon + 權重衰減 + RMS 匹配 + QK-Clip，通過更新後重縮放 Wq/Wk 抑制注意力 logits 爆炸），在 15.5T token 上預訓練且全程零 loss 尖峰。

K3 在此基礎上做了五組改動。下面先補一節預備知識（注意力、KV 緩存、MLA 是什麼），再逐組拆解——不需要機器學習基礎也能讀，但會講到機制層面。

### 0. 預備知識：注意力、KV 緩存與 MLA

**注意力機制在算什麼。**模型把每個字（token）表示成一個幾千維的向量。生成新字時，當前字要向前文所有字發起一次"查詢"：當前字算出一個查詢向量 q；前文每個字都備好兩樣東西——鍵向量 k（"我是什麼"）和值向量 v（"我攜帶什麼信息"）。注意力分三步：拿 q 和每個 k 算相似度得到分數 → 用 softmax 把分數歸一化成權重 → 按權重加權求和所有的 v，得到"從前文調閱回來的信息"。直覺上就是按相關性翻檔案。實際模型用的是多頭注意力（MHA）：把這套流程並行做幾十上百份，每份叫一個"頭"，各頭在不同的子空間裡各看各的側面（有的盯語法搭配，有的盯遠距離指代），最後把各頭結果拼接起來。

**KV 緩存是長上下文的顯存黑洞。**生成是逐字進行的，前文每個字的 k 和 v 在整個生成過程中要被反覆查詢。為免每一步都重算，推理框架把它們全部存在顯存裡——這就是 KV 緩存。它的體積 = 層數 × 頭數 × 每頭維度 × 2（k 和 v 各一份）× 上下文長度，隨文本長度線性膨脹。對幾十層、上百頭的大模型，上下文到幾十萬 token 時，KV 緩存能吃掉幾百 GB，比模型權重本身還大。於是有了一條"壓縮 k/v"的演進線：MQA 讓所有頭共用一份 k/v（省得最狠但傷質量）；GQA 讓每組頭共用一份（折中方案，Llama 系列採用）。

**MLA（Multi-head Latent Attention，多頭潛注意力）：用低秩壓縮替代粗暴共享。**DeepSeek-V2 提出，DeepSeek-V3 和 Kimi K2 沿用。核心想法：不直接緩存每個頭的完整 k、v，而是先把每個字的信息壓進一個很小的"潛向量"（低秩壓縮，幾百維），只緩存這個潛向量；使用時再通過上投影矩陣從潛向量恢復出各頭的 k、v。數學上利用矩陣乘法結合律，上投影矩陣可以被吸收進查詢和輸出側的矩陣裡，恢復過程幾乎不額外花時間。效果：KV 緩存壓到 MHA 的幾十分之一；又因為各頭是從同一個潛向量差異化恢復的（不是 MQA 那種粗暴共用同一份），質量基本不掉，DeepSeek 的報告裡甚至略優於 MHA。一句話：**MLA = 全注意力的能力，幾十分之一的緩存。**

記住這條線索再往下看：K2 是純 MLA 架構；K3 只在 1/4 的層保留 MLA（加了輸出門控），另外 3/4 換成了下面要講的 KDA——MLA 壓的是"緩存"，KDA 動的是"計算本質"。

### 1. Kimi Delta Attention（KDA）：把 3/4 的注意力層換成線性注意力

K3 最大的架構變化，動的是注意力的計算本質。

**全注意力為什麼必然又慢又貴。**預備知識裡說了，每個新字要和前文所有字算一遍相似度：第 n 個字要算 n 次，全文下來總計算量按 n² 增長——文本長 10 倍，計算量漲 100 倍，100 萬 token 時 n² 已是萬億量級。同時 KV 緩存隨長度線性膨脹。MLA 壓掉了緩存那一頭，但"每個字回看全部歷史"的 n² 計算本質沒變。

**線性注意力：把"翻檔案"改成"記筆記"。**去掉 softmax 之後，注意力在數學上可以改寫成一個遞推過程：維護一個固定大小的狀態矩陣 S（可以理解為一塊尺寸固定的記憶黑板），每讀一個字，就把它的鍵值信息寫上去（S ← S + v·kᵀ，一次外積寫入）；輪到生成時，拿當前的查詢 q 到黑板上取信息（輸出 = S·q）。於是每個字的處理代價是常數，與前文多長無關——計算量隨長度線性增長，"緩存"從隨長度膨脹的 KV 變成固定一塊黑板。代價也很本質：黑板尺寸固定，信息只能有損壓縮，寫多了互相覆蓋，"從 80 萬字前的合同裡精確摳出某個數字"這類大海撈針會變差。這是線性注意力提出多年一直沒能上位的原因。

**delta 規則：先擦再寫，黑板不糊。**樸素線性注意力只寫不擦，純累加，越寫越糊。delta 規則把寫入改成三步：先拿新鍵 k 去黑板上查出舊值（S·k），算出舊值和新值 v 的差距，再按寫入強度 β 做修正——更新式大意是 S ← S − β·(S·k − v)·kᵀ，即"先擦掉過時的那一塊，再寫上新的"。數學上這等價於對"黑板能否用 k 正確查出 v"這個目標做一步在線梯度下降，學界稱為 DeltaNet 路線。KDA 是這條路線的門控加強版：給狀態矩陣的每個通道配獨立的遺忘門（細粒度對角門控），每個維度自己決定衰減多快、保留多久，並配套了分塊並行算法讓這種遞推在 GPU 上高效訓練——這正是月之暗面 2025 年 10 月 Kimi Linear 論文的核心貢獻，KDA 之名即出於此。

**K3 的混合配比與保底設計。**全模型約 3/4 的層用 KDA（拿走線性注意力的成本曲線），每 4 層保留 1 層帶輸出門控的 MLA 全注意力。分工邏輯：線性層負責"大體記住、便宜地處理長流水"，稀疏保留的全注意力層負責"關鍵時刻回原文精確檢索"——大海撈針的能力由這 1/4 兜底。Kimi Linear 論文在 48B 規模驗證過 3:1 配比：KV 緩存省約 75%，百萬 token 解碼吞吐數倍提升，質量不輸純 MLA 基線（論文口徑）。K3 是這條路線第一次被推上萬億級旗艦，官方稱百萬 token 上下文解碼速度最高提升 6.3 倍（**廠商自報，驗證投票 2-1，是全文最弱的一個數字，**權重開放前無法復現）。

### 2. Attention Residuals（AttnRes）：讓深層網絡能"回頭查任何一層"

**背景：殘差流是 Transformer 的主幹總線。**大模型由幾十上百個結構相同的層堆疊而成，信息逐層加工。如果每層都把上一層的結果徹底重做一遍，信息傳到深層早就面目全非，訓練信號（梯度）也傳不回淺層——深度網絡根本練不動。2015 年 ResNet 給出的解法沿用至今：每層的輸出 = 輸入 + 本層算出的增量（x ← x + f(x)）。這條貫穿全網的 x 被稱為殘差流，像一條總線：每一層從總線上讀取當前狀態，做自己的加工（注意力層負責在字與字之間搬運信息，前饋層負責對每個字做深加工），再把增量寫回總線。相當於流水線上每個工位只在半成品上做小改動，原件始終順著傳送帶往下傳。

**它的侷限：總線上只有"當前總和"，歷史版本全部丟棄。**第 60 層從總線上拿到的，是前 59 層所有增量疊加後的結果。可解釋性研究早已發現，不同深度的層各有分工：淺層保留詞形、局部語法這類原始特徵，深層逐漸加工出抽象語義。如果第 60 層需要的恰恰是第 3 層的原始特徵，它只能指望這份信息在幾十層的寫入中沒被稀釋沖淡——總線不保留歷史快照，沒有任何直接通道可以回去取。

**AttnRes 的做法：把注意力從"序列方向"複製一份到"深度方向"。**官方描述是"從任意較早層選擇性檢索表徵，替代固定的殘差累加"：每層不再只被動接收傳送帶遞來的總和，而是能以當前狀態為查詢，對之前各層的輸出快照做一次選擇性檢索——現在最需要哪一層的中間產物，就直接去調哪一層，按相關性加權取回。可以這樣對照理解：序列注意力回答"該看前文哪個字"，AttnRes 回答"該看前面哪一層"。代價是要保留各層表徵供檢索，用一定顯存換訓練效率（具體實現以論文為準）。打個比方：傳統殘差像傳話遊戲裡每人只能拿到前面所有人疊加改寫過的一張紙，AttnRes 允許直接翻任何一位前手的原始筆記。

**效果與邊界：**這項工作有獨立論文（arXiv:2603.15031），報告約 25% 訓練效率提升——官方表述是"匹配用 1.25 倍算力訓練的基線的 loss"，即同樣效果少花約 1/5 算力。注意測量口徑：這是在 48B 總參/3B 激活的縮小版模型、1.4T token 上得到的，K3 全量訓練中的實際收益要等技術報告披露。

### 3. Stable LatentMoE：896 個專家與分位數負載均衡

**背景：MoE 改造的是前饋層。**Transformer 每層有兩大件：注意力（在字與字之間搬運信息）和前饋網絡（對每個字獨立做深加工——參數的大頭，模型的知識主要存在這裡）。MoE 把每層那個巨大的前饋網絡替換成 N 個小前饋網絡（"專家"）加一個路由器：每個字進來，路由器對全部專家打分，只取分數最高的少數幾個，這個字只流經被選中的專家，輸出再按路由分數加權合併。這樣總參數可以做得極大（決定知識容量上限），而每個字實際動用的計算只有一小撮（決定推理成本）。K3 是 896 個專家取 16 個（1.8%）——總參數 2.8 萬億，但每生成一個字只動用約 500 億參數，推理賬單跟一個 50B 稠密模型同量級。這就是"2.8T 的知識容量，50B 的賬單"。

**行業趨勢：專家越切越細。**DeepSeek-V3 是 256 選 8，K2 是 384 選 8，K3 直接推到 896 選 16。專家多而小，可選的組合方式指數級增多，分工可以更專業化，同樣的激活預算下表達力更強；代價是路由器的調度難度和系統工程複雜度同步上升——專家要分佈在大量 GPU 上，誰被選中就要把數據路由到誰那裡。

**負載均衡為什麼是 MoE 的第一工程難題。**訓練中路由器會形成正反饋：某個專家被選得多 → 練得好 → 打分更高 → 被選得更多。放任不管的結局是兩極分化：少數熱門專家過載（它們所在的 GPU 成為全局瓶頸，其他 GPU 圍觀空轉），多數冷門專家餓死（白佔顯存沒練出本事）。經典解法是輔助損失（Switch Transformer 一脈）：往訓練目標里加一項"分配越不均、罰得越重"的懲罰。問題是罰項和"把語言模型練好"的主目標天然打架——罰重了，路由器為了均衡把字硬塞給不合適的專家，模型質量受損；罰輕了又壓不住分化。DeepSeek-V3 開創了"免輔助損失"路線：給每個專家掛一個動態偏置，過載就調低、飢餓就調高，隻影響"選誰"、不汙染訓練目標本身。

**K3 的分位數負載均衡（Quantile Balancing）：**沿著"不靠罰款"再進一步——直接從路由分數分佈的分位數推導專家分配，直覺上相當於按全批數據的分數排位來劃分流閾值，均衡由分配機制本身保證，既不加懲罰項，也不需要手工調偏置的更新速率。名字裡的 Stable 應當指的就是路由和訓練的穩定性；Latent（潛空間）具體指什麼結構（是否與 MLA 式的低秩壓縮同源）官方博客未展開，要等技術報告披露。

### 4. Per-Head Muon 優化器 + SiTU 激活函數

**背景：優化器在訓練循環裡的角色。**訓練 = 前向傳播算損失 → 反向傳播算梯度 → 優化器決定"依據梯度，實際怎麼改這幾萬億個參數"。行業默認的 AdamW 為每個參數單獨維護梯度的一階動量（近期平均方向）和二階動量（近期波動幅度），逐參數自適應縮放步長——它把每個參數當作獨立個體。

**Muon 的洞見：矩陣參數應該按矩陣整體來優化。**神經網絡的絕大部分參數以矩陣形式存在（每個矩陣就是一次線性變換），矩陣的方向結構是有意義的。實踐中梯度矩陣的能量往往集中在少數幾個方向上（奇異值分佈極度不均），AdamW 式的逐元素更新會讓這幾個強方向獨吞更新量、弱方向被淹沒。Muon 的做法：在動量矩陣上跑幾步 Newton-Schulz 迭代做近似正交化，把更新矩陣的奇異值拉平——讓所有方向等幅推進。實證效果是同等數據學得更快。月之暗面是這條路線最大的下注者：K2 的 MuonClip = Muon + 權重衰減 + 學習率 RMS 對齊 + QK-Clip。其中 QK-Clip 專治 Muon 在超大規模訓練中的獨有隱患——注意力打分（q·k 內積）數值爆炸導致訓練崩潰：逐頭監控最大注意力 logit，一旦超過閾值（τ=100）就按比例重縮放該頭的查詢、鍵投影矩陣，把數值拉回安全區。戰果是 1 萬億參數、15.5T token 預訓練全程零 loss 尖峰——loss 曲線上一次崩潰都沒有，這在萬億級訓練裡是非常硬的工程成績。

**K3 的 Per-Head Muon：正交化粒度從整塊矩陣切到每個注意力頭。**注意力的投影參數在存儲上是一整塊大矩陣，但邏輯上是幾十個頭的子矩陣拼接（預備知識裡講過，各頭分工不同）。對拼接後的大矩陣整體做正交化，等於強迫所有頭共享一套"步幅均衡"，梯度結構差異大的頭會互相干擾；Per-Head Muon 按頭切塊、逐塊獨立正交化，每個頭按自己的梯度結構調整步伐。這與 QK-Clip 逐頭裁剪一脈相承——K2 的報告就發現數值爆炸往往只發生在個別頭上，"按頭處理"是更對症的粒度。

**SiTU（Sigmoid Tanh Unit）：換了激活函數。**激活函數是層內線性變換之間插入的非線性（沒有非線性，一百層網絡在數學上塌縮成一層）。近年主流是 SwiGLU（門控線性單元家族：一路做變換、一路做門控相乘）。SiTU 從命名看是 sigmoid 門與 tanh 變換的組合，同屬門控家族，但官方未披露具體形式、設計動機與消融數據，細節待技術報告。

### 5. 從 SFT 階段起的量化感知訓練（MXFP4 權重 + MXFP8 激活）

**背景：精度格式是顯存、帶寬、算力的三重槓桿。**模型參數默認用 16 比特浮點數（BF16）存。降到 8 比特、4 比特，三樣東西同時受益：顯存佔用等比例下降；顯存帶寬等比例提速——推理速度的常見瓶頸不是算力而是"把權重一遍遍從顯存搬進計算單元"的搬運速度；新一代 GPU 的低精度矩陣單元吞吐還成倍高於 16 比特（英偉達 Hopper 一代原生支持 FP8，Blackwell 一代原生支持 FP4）。

**MX 微縮格式：塊級共享縮放因子，解決"4 比特存不下"的矛盾。**4 比特浮點（1 位符號 + 2 位指數 + 1 位尾數）只能表達 16 個離散值，直接拿來存權重誤差不可接受。MX（Microscaling，微軟/英偉達/AMD 等共同制定的開放標準）的做法：每 32 個數編成一塊，塊內共享一個 8 比特的縮放因子，每個數自己只存 4 比特——相當於 32 個數合租一個"數量級"，各自只記有效數字。攤薄後約合 4.25 比特/參數，動態範圍卻大幅恢復。K3 的搭配是 MXFP4 存權重、MXFP8 存激活值（激活的數值分佈比權重更飄忽，8 比特更穩妥）。

**量化感知訓練（QAT）對比訓練後量化（PTQ）。**傳統 PTQ 是高精度練完再整體壓縮——模型訓練時從沒見過量化誤差，能力受損只能事後修補，像拍完高清照再壓圖。QAT 反過來：訓練時前向傳播就用量化後的權重參與計算（反向傳播用"直通估計"技巧把梯度傳回高精度主副本），模型在訓練中就學會把重要信息安置在低精度也表達得住的地方。K3 從監督微調（SFT）階段起全程 QAT——發佈出來的低精度權重是"原生"的，不是壓縮殘次品。

**部署賬，也是這一條對開源的真正意義：**2.8 萬億參數按 BF16 存，光權重就約 5.6TB 顯存，幾乎沒人部署得起；MXFP4 壓到約 1.5TB（含縮放因子開銷），砍掉四分之三——再加上 KDA 把 KV 緩存也砍掉大半，"3T 級模型開放權重且真有人部署得起"這件事才成立。對想私有化部署的團隊，這是實質利好而非姿態。

**關於"2.5 倍擴展效率"的準確讀法：**官方原文的歸因是"結構性改動 + 精煉的訓練與數據配方"共同作用，**不能**把 2.5 倍單獨記在架構頭上（這個錯誤歸因在核實中被 0-3 否決）。且該數字為廠商自報，技術報告發布前無法獨立驗證。

## 三、真實水平：獨立評測怎麼說

這是對"講懂 K3"最關鍵的部分，因為廠商基準和獨立評測給出的畫面並不完全一致。

### 獨立評測（Artificial Analysis，2026-07-17）

- 智能指數 **57 分，總排名第 3**——與 Claude Opus 4.8、GPT-5.5 同檔，落後 Claude Fable 5（59.86）和 GPT-5.6 Sol。
- **Agent 類基準是最強項：**GDPval-AA v2 Elo 1668（超過 GPT-5.5 的 1494 和 Opus 4.8 的 1600，低於 Fable 5 的 1750 和 GPT-5.6 Sol 的 1748）；AutomationBench-AA 以 53% 排第 1。
- **成本效率突出：**每任務實測成本 $0.94，約為 Opus 4.8（$1.80）的一半；輸出 token 比 K2.6 少 21%（132M 對 166M），即"話變少了但更準了"。

### 社區盲測

Arena.ai 的 Frontend Code Arena（前端代碼盲測）中以 1679 分排第 1，超過 Claude Fable 5 的 1631，較 K2.6 從第 18 名躍升 17 位（標註為初步結果，且僅此單一基準）。

### 廠商自報基準（未獨立復現，謹慎採信）

月之暗面自己的定位很誠實：**承認整體落後 Fable 5 和 GPT-5.6 Sol，**但稱編碼與 Agent 基準上大體勝過 Opus 4.8 和 GPT-5.5。MarkTechPost 整理的 11 項基準中，K3 在 5 項領先（Program Bench、SWE Marathon、BrowseComp、Automation Bench、OmniDocBench），但在最難的推理和倉庫級任務上落後：DeepSWE 67.5 對 GPT-5.6 Sol 的 73.0，FrontierSWE 81.2 對 Fable 5 的 86.6，HLE-Full 43.5 對 53.3。

**注意：**Fortune 報道的"與 Fable 5 表現相當"是過度拔高，已被證偽——正確表述是官方自認落後於 Fable 5，但差距在收窄。

### 綜合判斷

K3 的真實位置：**開源模型第 1、全球第三檔、Agent 任務尤其能打、性價比是同檔最強。**它沒有追平最前沿的兩家（Fable 5、GPT-5.6 Sol），但把"開源模型與閉源頂尖的差距"壓到了歷史最小。

## 四、定價與開源：便宜中國模型時代的落幕信號

- **縱向看是大幅漲價：**未緩存輸入 $3/M，是 K2 發佈價（$0.60）的 5 倍。The Decoder 的評論標題很點題——"超便宜中國 AI 時代的終結信號"。
- **橫向看仍有性價比：**輸出 $15/M，高於 GLM-5.2（$4.40）和 DeepSeek V4 Pro（$0.87），但只有 Opus 4.8（$25）的六成、Claude Fable 5（$50）的三成。緩存命中輸入 $0.30/M 對 Agent 場景（大量重複上下文）很友好。
- **開源承諾：**2026-07-27 前開放完整權重，號稱"全球首個 3T 參數級開源模型"（實際 2.8T，官方話術口徑）。截至本文寫作日權重尚未上 HuggingFace，"開源"仍處承諾階段；許可條款（是否沿用 K2 的修改版 MIT 及商用歸屬要求）未披露。

## 五、給 Agent / 基模方向從業者的幾點啟示

1. **架構方向的信號：**混合線性注意力（3/4 線性 + 1/4 全注意力）在旗艦規模上被驗證可行，這是繼 MiniMax、Qwen 之後又一家頭部廠商押注線性注意力路線，長上下文 Agent 的推理成本曲線會繼續下移。
2. **稀疏度繼續推向極限：**896 選 16（1.8%）的稀疏度比 K2（384 選 8，約 2.1%）更激進，"總參數狂飆、激活參數剋制"仍是共識路徑。
3. **量化感知訓練前移到 SFT 階段**是值得注意的工程決策——低精度不再是部署階段的妥協，而是訓練階段的一等公民。
4. **Agent 基準與通用智能基準的分化**在 K3 身上非常明顯：它在 GDPval、AutomationBench、前端代碼上能贏 Opus 4.8，但在 HLE 這類最難推理任務上差距仍大。選型時"看什麼榜"比"看總榜"更重要。
5. **緩存定價結構（命中打一折）**加上 1M 上下文，對多輪 Agent 工作流的實際成本影響比牌面單價更大，測算成本時要按自己的緩存命中率算。

## 六、信息可信度分級與待解問題

**最紮實：**K2 基線（有技術報告 + 開放權重）；AA 獨立評測數字；官方定價頁數字。

**較紮實但溯源單一：**K3 全部架構細節（16/896、KDA、AttnRes 等）——雖經多方轉述交叉印證，但最終都來自月之暗面單方披露，要等權重開放後從 config.json 獨立確認。

**廠商自報、待復現：**2.5 倍擴展效率、6.3 倍解碼加速（全文最弱數字）、25% 訓練效率（小模型上測得）、編碼/Agent 勝過 Opus 4.8/GPT-5.5 的自報基準。

**已證偽、勿引用：**2.7T 參數量（Fortune）；"與 Fable 5 相當"（Fortune）；把 2.5 倍效率單獨歸因於架構。

**待技術報告解答的問題：**
- 預訓練數據規模（token 數）、後訓練/RL 方法、完整優化器配置（目前只知 Per-Head Muon 和 SFT 起步的量化感知訓練，K2 的 15.5T token 不能外推）。
- 開源許可具體條款；2.8T 權重的實際部署門檻（顯存需求、推理框架對 MXFP4 的支持）。
- 精確激活參數量（約 50B 為社區推算）。
